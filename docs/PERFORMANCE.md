# 性能检查

## v0.7.0

2026-10-05，使用现有 11 项资源登记的独立副本，禁用自动备份并只读个人项目。最终测量窗口构造与显示约 0.775 秒；14 秒运行期最长界面心跳间隔约 0.079 秒。测量包含 cProfile 开销，不包含 Python / 冻结运行时加载，结果只代表本机。

今日使用后台单次读取，启动不重复排队。文件变化短防抖，隐藏的日常 Markdown 页面停止刷新，切换回来重新读取。资源索引按文件时间和大小复用；原进程状态仅在数据安全保护概览按需检测。关闭窗口时，后台每日读取使用已捕获的配置快照并响应取消，不再重新打开 SQLite。

## v0.6.1

2026-10-05，在本机 Windows 使用现有 11 项资源配置测试。性能探针使用独立数据目录；个人项目和备份正文未改动。

主要问题是启动、项目读取开始和结束时，工作台重复扫描所有进程的名称、完整路径和命令行。初始测量中，4 次工作台更新导致 16 次进程全量扫描，累计约 24 秒。界面在这些同步扫描期间无法正常响应。

修复后的同一轮测试，窗口构造与显示约 0.6～0.7 秒，原测量约 7.03 秒。这不包括 Python/打包运行时加载。最终 14 秒运行期的界面心跳最长间隔约 55 毫秒；进程清单只采集 2 次。测量结果只代表这台电脑。

改动：

- 进程检测改为后台单任务，上一轮未完成不重复排队。
- 一次进程清单供全部 Agent 使用；只读取 Node/Bun/Deno 等相关 CLI 宿主的命令行。Windows 用原生进程快照获取名称，避免逐个查询所有进程的可执行文件。
- 隐藏工作台停止进程轮询。隐藏操作流水或无任务运行时，停止每秒刷新。
- 任务列表只读取摘要，选中行才读取日志正文；内容未变化时保留表格控件和详情。
- 项目按需加载；切换状态、任务、日志、笔记标签复用已读取内容。Obsidian 外部文件变化仍自动重新读取。
- 文档读取不再连带重建所有管理页面；相同目录卡片复用，备份状态在每轮工作台更新中只计算一次。
- 移除已经没有调用方的七天活动统计函数；保留备份、校验、恢复与项目生命周期逻辑。

验证包含原有备份/恢复测试，以及新增的后台响应、单次扫描、任务列表按需读取和项目标签复用检查。真实文件变更联动使用测试工作区验证。
