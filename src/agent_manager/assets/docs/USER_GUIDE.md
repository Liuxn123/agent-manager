# Agent 管家使用说明

适用版本：v0.6.0。按模块阅读即可。

## 1. 先看这里

管家管理本地资料：Hermes、Codex 等 Agent 的记录、技能、配置，以及 myself 笔记。它也按你的编号规范创建、记录、归档项目。

日常用法：打开工作台 → 看需要处理的资料 → 检查状态 → 立即备份。

第一次创建 Agent 或 myself 的加密备份时，设置一个统一密码。以后本次打开期间，新建的 .amb 备份都用它。请单独记住密码；关闭管家后会忘记本次输入。

## 2. 工作台

“需要你处理”指出缺少备份、未校验或最近操作失败的资料。双击进入对应页面；失败操作进入排查记录。“最近备份”显示最近保存的资料。

运行状态来自最近检测，不代表实时结果；点击检查状态刷新。

## 3. 本地 Hermes

顶部选择实例，通常只有一个，不再占用大块列表。

- 检查状态：核对运行目录、备份环境、会话、技能和记忆数量。
- 立即备份：使用已有原生备份工具和密钥。
- 校验备份：检查现有快照。
- 恢复备份：先预览，再确认。可能替换当前资料，先保存当前版本。
- 会话与技能：浏览会话和 SKILL.md，正文只在查看窗口显示。
- 备份提交：查看原生仓库的历史。
- 打开 Hermes 目录：进入运行目录。

“目录与操作”可复制完整路径；“最近操作”查看该实例的操作结果。本地启动、停止及 Workspace 自动登记不再作为日常入口。

## 4. 服务器 Hermes

顶部选择 Profile。你的服务器有 pigzhulin、gugu 两个命名 Profile，默认目录另保留在服务器上。

**当前服务器共用网关和原生备份仓库。分别显示 Profile 资料目录，不表示它们拥有独立快照。备份 / 恢复沿用现有整套服务器工具。** 重启共享网关会影响使用该服务的 Profile。

检查状态核对 SSH、目录、服务和密钥文件。网关日志只读最近 80 行。“查看服务器 Profiles”只读发现真实目录，不创建或切换 Profile。

连接需要：网络可达、SSH 账号、端口、可读取私钥、已核对主机指纹。换电脑时，原电脑外部的私钥需要你另行提供。

服务器恢复到远端新目录 / 空目录，先预览并校验；不自动切换生产网关。运行环境和服务切换仍需单独验证。

## 5. 本地项目

普通项目以创建、状态、任务、日志、归档和重新启用为主。myself 在同页有自己的备份、恢复和配置按钮，沿用独立 Git 仓库。

1. 选择工作区：已有目录必须包含 agent/projects.json；空目录可以初始化。
2. 新建项目：填写名称和目标，一键分配编号、建立状态、任务、日志和 Obsidian 入口。
3. 当前状态 / 任务入口：必要时编辑，保留 project_id 和有效状态。
4. 写日志：分别填写完成内容、验证、问题和下一步，追加到原来的 agent/HANDOFF.md。
5. 项目日志：默认查看最近一条；下拉选择历史。“查看完整交接原文”保留原文入口。
6. 归档项目：预览确认后移动到 archive，更新登记和入口。归档是整理，不是备份。
7. 重新启用：切到已归档，选择项目后重新启用，保留编号和历史。

Obsidian 与管家使用同一份真实文件。“Obsidian 中打开”打开当前文档或所选笔记。外部修改会刷新；普通项目不检查自己的 Git 仓库。

## 6. 其他 Agent

登记项目目录和本地记录目录。只需要记录时，可以不填项目目录。

检查状态区分资料是否存在与原程序是否运行。备份失败是操作结果，不能据此判断 Codex 已停止。浏览本地记录读取已识别格式。立即备份将登记的资料合成加密 .amb；试一次恢复会实际恢复到临时目录并校验，保留原目录。

Codex 备份排除线程写入锁、沙箱和 provisioning guard 等运行文件。SQLite 优先只读快照；没有日志伴随文件的静止数据库，在隔离副本中检查。会话 JSONL 保存读取开始时已有的完整记录，随后新增内容留待下次备份。**最终迁移前，退出原应用再备份。** 必要文件无法读取时停止并指出路径，不默默漏掉。

Token 用量手动读取 Codex 日志的用量字段，显示输入、输出以及缓存 / 推理子集。重复快照不重复计数。它是有限本地统计，不是账单，不拆分每日费用，不联网查价格。最多 200 个文件、每个末尾 2 MiB、总计 64 MiB；截断和不可读取数量会显示。其他 Agent 没有已验证解析器时明确提示，不显示虚假的零消耗。

轻量读取思路参考 [TokenTracker](https://github.com/xiufengsun/TokenTracker)，未安装其后台服务或框架。

## 7. 备份与迁移

点击开始换电脑检查，补齐任务清单：

1. 提供 .amb 文件。
2. 输入创建时的密码；与已输入统一密码相同，可留空使用它。
3. 自动检查解密结果和每个文件的完整性。
4. 选择新目录 / 空目录及资料子目录，检查冲突。
5. 阅读恢复预览，确认后恢复并登记新路径。

失败显示原因；预览后备份改变或目标不再为空，会阻止执行。恢复完成表示资料已经恢复并校验。

**原应用能否直接续聊，需要在原应用验证。** 管家不会自动安装软件、恢复云端独有聊天、迁移系统钥匙串或跳过登录。“原应用已安装”是你的确认，不是自动检测。恢复后核对版本、资料位置、项目路径和登录；可先在管家浏览本地记录。

Agent 备份仓库只整理已校验加密包副本，myself 不放进去。大包用 U 盘携带。整理不等于自动提交推送 Git。

## 8. 工作总结

我的工作总结保存你填写的总体进展、问题和下一步，按日期追加到 data/work-summary.md，随完整便携目录带走。具体项目日志仍写在项目原文件。

操作记录 / 排查失败保留检查、备份和恢复状态及脱敏日志，可以查看失败详情或请求取消任务。不会自动复制完整 Agent 对话到总结。

## 9. 设置

常用项只有：备份位置和统一备份密码。

默认位置适合 U 盘。更改位置只影响以后新备份，已有文件不会自动搬家。

统一密码本次打开期间用于新建 Agent / myself .amb。更换不会改变旧包密码；恢复旧包仍输入原密码。Hermes 原生备份沿用现有密钥。忘记本次密码不会删除备份。

清理旧备份可设置自动保留份数，只有自动备份成功校验后才清理。自动备份需要在具体资料编辑中开启，保持管家打开；原 Agent 正在运行时会跳过自动备份。

电脑维护集中登记清单导入导出、环境检查、旧版密码记忆解锁。登记清单只保存位置，不含完整资料。

## 10. U 盘与换电脑

退出管家后复制整个便携目录，保留 portable.json、data、backups、restored 和全部运行文件。不要只复制 exe。不同系统使用对应 Windows / Linux / macOS 运行包。

外部目录如 E:\obsidian、用户目录下的 .codex、SSH 私钥，不会因复制管家而自动随行。先备份或另外携带，再在新电脑执行任务清单。统一密码重新输入。

升级只替换运行文件，保留 data、backups、restored。U 盘盘符改变时内部路径会重新解析；外部路径需要核对。

## 11. 常见问题

备份失败：到操作记录 / 排查失败查看原因。必要文件权限不足会指出路径；持续改写的普通文件仍可能需要退出原应用后重试。

密码错误：使用创建这份备份的原密码；更换统一密码不会修改旧包，没有密码无法解密。

字显示不全：按钮支持自动换行，完整路径在目录与操作中查看 / 复制。最小窗口 960 × 660。

Obsidian 打不开：安装后运行一次，注册 obsidian:// 接口并核对工作区入口。

恢复范围与验证见随包 [RESTORE_SCOPE.md](RESTORE_SCOPE.md)。

## 12. 技能与工具

查看 Agent 现有 Skills，导入本地技能到通用库，确认后复制给目标 Agent。新建、编辑自有通用提示词。

MCP 清单只读配置并隐藏授权内容，不自动启用工具或改写原配置。地址、依赖和凭据仍需核对。通用库保存在 data/asset-library，完整便携目录可随行，或点备份通用库创建加密包。

设计参考 [Skills Manager](https://github.com/xingkongliang/skills-manager)，保留精简的本地管理方式。
