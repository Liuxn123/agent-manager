# Agent 管家 v0.7.8 使用说明

## 1. 先看这里

Agent 管家是每天开始 Agent 工作的个人工作台。先看今天做什么，再进入项目，找到 Agent 与资源；需要备份时进入数据安全。

侧栏只有六项：今日、项目、Agent、资源库、数据安全、设置。默认打开今日。原有资源登记、项目、备份、口令机制继续使用，不必重新添加。

建议先在“项目”选择自己的规范工作区，再在“今日”写今天的计划。没有工作区也能先写每日计划和收藏资源。

## 2. 今日

默认显示今天。任务区只保留“今日要做”和 Todo：“今日要做”显示正在查看日期的任务，可直接勾选；Todo 可选截止日期，列表显示其他日期尚未完成的任务，双击后进入对应日期。顶部日期框可以选择过去或未来，左右箭头切换一天，“回到今天”返回。项目与备份状态仍表示当前状态。

点“日程总览”，选择以下范围：

- **未来 30 天**：含今天的未来安排与未完成任务。
- **所有未完成任务**：也包括过去日期仍没完成的任务。标注“未完成（过去日期）”，不会自动挪到今天。
- **全部已登记日程**：跨日期查看已有安排；勾选“显示已完成任务”可回顾完成记录。
- **自选日期范围**：选择开始、结束日期，查看某一周、某个月或更远的计划。

双击事项或选中后点“打开所选日期”，进入该日期编辑或勾选任务。总览也能添加事项：选中行时默认使用该行日期，添加窗口可以另选日期。计划仍写入 `每日/YYYY-MM-DD.md`，旧格式继续使用，不生成第二份总日程文件；只浏览空日期不会创建文件。Obsidian 修改这些文件后会刷新总览，也可手动刷新。

总览只读取“每日”目录，单文件最多 1 MB、单次最多 1000 个日期文件 / 4000 项 / 10 MB；达到上限会提示缩小日期范围。不会扫描项目正文或 Agent 对话。

这里显示 Todo、所选日期的可勾选任务、需要继续的项目、最近进入的项目、待处理异常和少量备份状态。日程和时间安排仍在“日程总览”中查看。

先看顶部三张卡片：今日要做完成数、待处理事项、可继续项目数。空白计划显示引导，统计不使用演示数字。

日常直接点“添加任务”或“添加日程”。任务只填写内容；日程可选时间，例如 `09:00–10:00`。这些内容仍保存为普通 Markdown，没有另一套数据库任务。

“编辑今日计划”编辑当前日期的 Markdown。“今日要做”和截止日期为当前日期的 Todo 都从这份文件读取；保存后两块清单会一起刷新。Todo 日期就是对应每日文件的日期。点复选框或选中任务后按空格完成，双击任务可打开计划编辑。

小窗口减少装饰并保留双栏，页面可滚动，长项目说明省略并可悬停查看全文。

项目卡片展示真实阶段与下一步；双击继续。最近工作表示最近从管家进入的项目。资料保护展示已记录的备份结果，不代表当前 Agent 或服务器已在线。点备份卡片进入对应数据安全登记。

点“编辑今日计划”，使用这个格式：

```markdown
# 2026-10-05

## 日程
- 09:00 Agent 管家开发
- 14:00 Hermes 测试

## 今日任务
- [ ] 测试恢复
- [ ] 完成阶段总结
- [ ] [高] 核对恢复结果 @10:00

## 工作记录
今天发现的问题可以记在这里。
```

日程是普通时间文字，不发送通知、不连接日历服务。任务可以直接勾选，程序写入 `[x]`；普通 `- 任务` 也能显示和勾选。其他 Markdown 内容保留。

点“Obsidian 中打开”编辑原文件。外部编辑或原子保存后自动刷新，程序重新获得焦点也会刷新。若编辑期间原文件改变，保存会停止，原文件不会被覆盖。

双击需要继续的项目进入项目。最近工作仅表示你从今日进入过的项目，不推测 Agent 对话内容。暂停项目与最近操作失败 / 中断显示在“需要我处理”；双击进入对应页面。旧版工作笔记仍可从页底查看。

午夜后首页会切换到新一天。新文件在第一次保存计划时创建，程序启动不会批量写入知识库。

## 3. 项目

选择包含 `agent/projects.json` 的工作区根目录；普通项目目录不是规范工作区。也可选择空目录初始化，随后点“新建项目”。编号按既有规范分配且不复用。

左侧点项目卡片，右侧先看项目名称、当前阶段和“下一步”。上方可按名称 / 编号搜索，切换未归档 / 已归档 / 全部项目。工作区按钮只显示简短名称，悬停可看完整路径。

当前状态分成六张卡片：目标与验收、当前进展、本阶段总结、下一步行动、风险 / 待确认、最近记录。宽窗口三栏，较小窗口两栏或一栏；小窗口可滚动右侧工作区，常用操作完整保留。内容取自已有 Markdown，未填写时显示提示，不生成虚构进度。

“查看状态原文”切换到完整 STATUS，未分类的个人说明和原格式仍在这里。“更多操作 → 编辑当前文档”可编辑 STATUS / TASKS；“更多操作 → 阶段与关联资料”修改阶段、Agent 和资源关联。阶段缺失的旧项目按原状态或“当前阶段”文字兼容显示；默认阶段有规划、进行中、测试、收尾、完成，也可输入自己的阶段名称。

“清单任务”表示已完成数 / 总数，识别 TASKS 中的复选框和含动作 / 任务、状态列的表格；表格中 done / completed / complete / 完成 / 已完成算完成，其他状态保留为未完成。代码块里的示例不计入。TASKS 若只是指向其他任务文件，则显示“任务入口”，不递归扫描或推算项目完成百分比。

日志数来自 HANDOFF 中按日期追加的记录，包含阶段总结；最近更新来自 STATUS 的 updated 字段，不代表 Agent 在线。关联资料只统计能找到的 Agent 与资源，找不到的引用仍在资源标签中保留并提示。

标签入口：当前状态 STATUS、任务 TASKS、日志 HANDOFF、笔记、阶段总结、资源。“写阶段总结”“查看项目资源”“写日志”在右侧项目标题下方；“Obsidian 中打开”打开当前标签对应的同一份文件。

STATUS 是进度真源，TASKS 按已有文件指定的任务真源使用，HANDOFF 按日期追加日志。任务入口只是展示 Markdown，不在 SQLite 再建立一套项目任务。

“写日志”追加最近发生的事；“更多操作 → 编辑当前文档”编辑 STATUS / TASKS，保存有原文冲突检查。项目笔记保存在真实“笔记”目录，Obsidian 与管家共用。外部修改后，状态卡片、任务统计与原文一起刷新。

“更多操作 → 归档项目”先预览再确认，移动到 archive，保留编号、正文、附件、日志与 Obsidian 联接。选择已归档的编号项目后同一菜单显示“重新启用”。移动期间自动释放管家文件监听，结束后恢复。打开文件夹、Obsidian 总览 / 归档索引和刷新索引也在这里。归档不等于备份。

旧 `L-` 项目显示“从旧归档继续”：打开已填名称、原路径和接续目标的新建窗口，确认后分配新 `P-` 编号，创建管理文件并引用原资料。原归档及业务文件不会移动或复制；可以修改名称与目标，也可以取消。

若提示“目录未移动，文件清单与预检一致”，原资料仍在原位置，关闭其他占用程序后重新预检即可。若提示“移动过程未全部完成”，保留两边目录，按提示中的 `agent/history/*-move.json` 核对失败步骤，不要手工删除或重复移动；记录保留具体系统错误。

## 4. 阶段总结

点“写阶段总结”，填写八个栏目：阶段目标、完成内容、验证结果、遇到的问题、失败方案、重要决策、经验与反思、下一阶段计划。

没有内容的栏目可写“暂无”；未验证的结果明确写“待验证”。空模板不能当作已完成总结保存。

“复制生成总结 Prompt”包含当前 STATUS、TASKS 与栏目模板。可粘贴到自己选的 Agent，审阅输出后粘贴回弹窗。管家本版不会自动发起 AI 调用。

保存把总结追加到原 HANDOFF；原交接和日志保留，不新增 SUMMARY / PROGRESS / REFLECTION。阶段总结标签按最近在前展示这些记录，“Obsidian 中打开”打开 HANDOFF 原文。

“阶段与关联资料”可勾选 Agent、Prompt、Skill 或其他资源；只把引用编号放进 STATUS。资源也能通过“适用项目”关联项目。失去登记的编号保留并提示未找到，程序不会擅自删除引用。

## 5. Agent

统一管理 Hermes、Codex、Claude Code、WorkBuddy、CodeBuddy 与其他 Agent。旧登记自动显示。

主要使用“打开常用入口”“查看记录”“相关资源”“写备注”“编辑登记”“查看目录”。没有深度适配时只使用可用的通用入口。

编辑登记保留原备份字段，可在可选区域补充安装位置、配置目录、网页入口和关联项目编号。网页入口只接受 http / https。应用启动沿用现有程序路径和参数；只控制管家自己启动的进程。

“写备注”创建或编辑资源库里的 Agent Markdown，正文不写入 SQLite。“相关资源”显示关联当前登记编号或适用该 Agent 类型的资料。

最近使用表示从管家打开入口的时间，登记状态不等于应用已运行。查看目录不会扫描项目 Git。服务器的日志、Profile 与网关控制继续通过已有适配器提供。

“备份与恢复”直接定位数据安全中的同一项登记，不复制另一份配置。

## 6. 资源库

点“收藏新资源”，选择 Prompt / Skill / MCP / Agent / 工具 / 网站 / GitHub 仓库 / 文章资料 / 模板 / 其他。

填写名称、一句话用途、标签、来源链接、可选本地路径、适用 Agent 和项目、备注及 Markdown 正文。标签与多个编号用逗号分隔。适用 Agent 可用登记编号或类型，如 codex / claude；适用项目用项目编号，如 P-2026-001。

收藏、已安装、已配置、已测试是人工记录的状态，程序不会替你验证安装。MCP 的用途、安装和配置说明直接记在正文。本版不连接 MCP，不执行 Skill 或 Prompt 中的命令。

搜索名称、标签、用途和正文；可筛类型或只看收藏。项目进入资源库时带项目筛选，可点“清除项目 / Agent 筛选”恢复全库。

“Obsidian 中打开”编辑真实文件；“打开来源”仅打开无内嵌凭据的 http / https 链接；“查看本地目录”打开登记位置。

也可直接把 Markdown 放进工作台的“资源”文件夹。例如：

```yaml
---
type: prompt
name: 项目阶段总结
tags:
  - 项目
  - 总结
agents:
  - codex
  - claude
projects:
  - P-2026-001
favorite: true
configured: false
tested: false
---
```

下面接 Markdown 正文。资源库只索引这一层的 `.md` 文件，最多 1000 个，每个 1 MB。错误 frontmatter 或重复 id 会显示提示，文件不会被删除。建议保留程序生成的 id，保证项目引用稳定；手写文件缺 id 时使用文件路径身份，并在编辑时保留它。

## 7. 数据安全

原备份能力集中于此，日常首页只显示必要状态。

“备份与恢复”选择本地 Hermes、服务器 Hermes、项目与 Obsidian 资料或其他 Agent。保留检查状态、立即备份、完整性校验、恢复预览、实际恢复与可用诊断。Hermes 使用原生仓库和密钥机制，其他 Agent / 项目使用加密 `.amb`。

服务器仍需正确 SSH 账号、主机指纹、私钥或 SSH Agent、远端目录与服务范围。Profile 可以有不同显示目录，但共用网关与完整备份范围；恢复到空目录，不自动启动网关。

“备份历史 / 换电脑”查看本机已有副本，或选择从其他电脑带来的 .amb。解密后检查文件，选择新目录 / 空目录，先预览再确认恢复。恢复登记保留原 id，路径指向新位置；启动程序不自动迁移。

“试一次恢复”解密到临时目录并比较文件，演练后删除临时目录，不覆盖原资料。错误密码、篡改或目标冲突会停止。

“操作记录”查看管家动作的结果，不是 Agent 对话。只保存操作状态与必要诊断，不保存浏览到的私密正文。“保护概览”可按需检查整体状态；进程检测仅在此区域显示时运行。

统一 .amb 密码可在设置输入，也可首次备份时输入；关闭程序后忘记本次密码。旧备份用原密码。自动备份与保留策略沿用原机制。专用 Agent 备份仓库只整理已校验的加密副本，myself 使用自己的 Git 仓库，项目 Git 不自动检测。

## 8. Obsidian 联动

项目使用原登记的入口联接或独立 Vault 策略；不复制项目正文。项目归档 / 重新启用后联接仍指向同一份实际资料。

每日与资源默认放在 `工作区/myself/Agent工作台`。没有项目工作区时使用 `管家数据/工作台`；设置能选择 Obsidian Vault 内另一个文件夹。

若提示没有知识库，先在 Obsidian 把该文件夹的上级作为 Vault 打开。管家不创建或改写 `.obsidian` 配置。未保存的今日计划还没有文件，先保存一次再打开。

改资料位置不会搬迁旧文件；把旧每日 / 资源文件夹人工复制到新位置，确认后再选择。项目规范仍由原工作区决定。

## 9. 设置

常用设置只有文字资料位置和备份位置。默认通常可以直接使用。

选择文字资料位置时，推荐选择自己的 Obsidian 知识库内的专用文件夹。如果想随 U 盘带走，选择便携程序目录内的资料文件夹。

更改备份目录只影响以后创建的备份，不搬动旧副本。高级区域调整自动备份保留数；只有新备份成功且旧副本可验证时才清理。电脑维护中的配置导入导出只包含登记和程序设置，不包含项目正文、聊天、备份密码或 SSH 私钥。

## 10. U 盘与换电脑

保留 `portable.json` 和整个便携目录，包括 exe、_internal、data、backups，以及你放在其中的文字资料。不要在移动或升级时只复制 exe。

目录内的 SQLite 配置路径随目录或盘符变化，原 .amb 格式继续兼容。目录外的 Obsidian、项目、记录、私钥或 Hermes 仓库不会自动装进 U 盘，换电脑需要携带、恢复或重新选择。

本版升级只新增工作台配置标记，不改旧项目、Agent id、备份格式或原笔记。旧 projects.json、STATUS、TASKS、HANDOFF、笔记、登记、备份和设置继续使用。

重要文字资料也要保护：可在数据安全登记工作台资料文件夹为项目 / Obsidian 备份；若它在 myself 内，myself 完整备份会包含它。程序配置导出不代替正文备份。

先恢复资料，再安装目标 Agent 的运行环境、核对登录与实际数据位置。记录能浏览，不代表原应用一定能直接续聊；跨系统路径或登录材料也可能需要手工处理。Hermes 使用独立原生恢复入口。

## 11. 常见问题

**项目列表为空：**先查看工作区按钮。未选择时，选择原来含 agent/projects.json 的工作区根目录；这不会删除或重建项目。未归档 / 已归档和搜索条件也会影响列表。源码和便携版可使用不同数据目录，设置中的数据位置用于核对。Windows start.cmd 在相邻 AgentManager-Portable 已安装时沿用它的数据；AGENT_MANAGER_DATA_DIR 仍可指定隔离数据。

**资源看起来消失：**点“显示全部资源”清除项目、Agent、类型、收藏和搜索筛选。从项目 / Agent 进入时会清除遗留筛选，新收藏自动填入当前关联。Agent 备注保存后在资源库立即查看。

**项目文档不完整：**详情显示缺失或不可读的文档，其他资料仍能查看。打开项目文件夹检查；管家不会用模板覆盖个人原文。


**能提前安排日程吗？** 可以。添加时选择日期，或用“日程总览”查看跨日期计划。日程由 Markdown 保存；本版不接外部日历服务，MCP 仅登记用途与配置说明。

**为什么项目总结没有单独文件？** 阶段总结追加到已有 HANDOFF，避免进度、总结、交接多份正文互相冲突。

**为什么保存提示文件已改变？** Obsidian 或其他程序修改了原文件。关闭弹窗，刷新后重新编辑；管家不会覆盖外部新内容。

**为什么资源没有出现在项目里？** 检查资源的适用项目编号，或在阶段与关联资料中勾选它；ID 引用必须一致。项目筛选可清除。

**为什么资源状态是“已测试”但实际上不能用？** 状态是人工登记，不是自动连接或检测结果。

**为什么“最近工作”为空？** 它记录从今日进入项目的使用时间，不读取 Agent 私密对话来推断。

**为什么 U 盘换电脑找不到知识库？** 原目录在 U 盘外，需要携带 / 恢复并重新选择。选择资料位置不会自动移动旧文件。

**恢复会覆盖正在用的文件吗？** .amb 默认只写新目录 / 空目录；Hermes 原生恢复遵循原有退出、预览、救援与确认流程。

**启动 DLL 错误怎么办？** 用对应系统的完整新运行包解压，不混用历史 _internal 文件；源码需虚拟环境与完整 Qt 依赖。仍失败时检查数据安全里的诊断或运行包启动诊断。
