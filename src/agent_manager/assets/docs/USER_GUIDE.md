# Agent 管家使用说明

适用版本：v0.5.0。可以按左边的模块直接阅读，不必一次看完。

## 1. 先看这里

这个工具帮你保存 Hermes、工作 Agent、项目和笔记的本地资料，并在需要时恢复。管家可以独立打开，不需要先启动 Hermes。

**日常用法：打开工作台 → 检查状态 → 选择需要保护的资料 → 立即备份。**

**换电脑用法：带走程序和备份 → 在新电脑打开管家 → 恢复到新文件夹 → 核对原应用的路径和登录。**

第一次试用，建议先选一个小项目备份，再做一次“恢复演练”。这会在临时目录里真实恢复文件，原项目不变。

| 你想做什么 | 去哪里 |
| --- | --- |
| 看整体情况 | 工作台 |
| 保存或恢复本机 Hermes | 本地 Hermes |
| 检查服务器、保存远端 Hermes | 服务器 Hermes |
| 按规范新建、管理日志、归档和重新启用项目 | 本地项目 → 项目管理 |
| 保存代码、知识库、Obsidian 笔记 | 本地项目 → 资料备份与 Obsidian |
| 保存 Codex、WorkBuddy 等的项目和本地记录 | 其他 Agent |
| 管理 Skills、MCP 配置清单与通用提示词 | 技能与工具 |
| 找备份、试恢复、换电脑 | 备份与迁移 |
| 看操作是否成功、为什么失败 | 活动记录 |
| 改保存位置、管理备份口令 | 设置 |

几个词的意思：**登记**是告诉管家文件在哪里；**备份**是保存当时的一份副本；**校验**是检查副本完整性；**恢复演练**是试着还原副本；**恢复**才会把资料实际放回目标目录。

**管理页的新入口：** 名称和路径会换行显示，名称列可拖动调宽。双击资源会打开右侧“目录与操作”，显示完整路径；“复制路径”方便粘贴，“打开目录”打开本机文件夹。服务器上的路径只提供复制。右侧“最近操作”显示所选资料最近 5 项管家操作，“目录与操作 → 查看全部操作记录”进入按该资源筛选的活动记录，可切回“全部资源”。小窗口的页签可通过右侧箭头切换。

## 2. 工作台

**用来做什么：** 一眼看见登记了哪些资料、有没有备份、最近的检查结果。

1. 点击“检查全部状态”，等待后台任务结束。
2. 在“资料保护”列表查看名称、最近备份、保护状态和连接情况。
3. 双击一项资料，进入对应模块。

“备份 Hermes”针对登记的第一项本地 Hermes。“查看最近备份”和“换电脑恢复”进入备份页。工作台不再提供笼统的本地记录搜索；需要找聊天时，在本地 Hermes 点“会话与技能”，或在其他 Agent 选中资料点“搜索记录”。

| 状态 | 你需要做什么 |
| --- | --- |
| 未备份 | 先创建一份备份 |
| 待校验 | 在对应模块重新校验 |
| 已校验 | 备份通过完整性检查 |
| 已演练 | 这份项目或 Agent 备份真实试恢复过 |
| 已过期 | 超过 48 小时未创建新副本；有变化就再备份，旧副本仍可恢复 |
| 目录需重选 | 编辑资料，选择这台电脑上的位置 |
| 状态后有“历史” | 这是过去的结果，点击检查状态刷新 |

“需要你处理”优先列出每项资料最新一次失败或中断的操作，或尚未备份、需要校验的资料。双击失败项查看该资料的操作记录，双击其他项进入管理页。“最近备份”列出近期副本，双击进入备份页。它们帮助你决定下一步，不统计 Agent 的工作量。

## 3. 本地 Hermes

**用来做什么：** 使用现有 Hermes 备份工具，保护会话、技能、记忆、配置及其恢复材料。

日常只需选中已登记的 Hermes，然后点“检查状态”或“立即备份”。检查后，右边“概览”显示会话、消息、技能和记忆数量；详细结果放在“配置与诊断”。

**会话与技能：** 点击同名按钮。在“会话”搜索标题或来源，选中条目查看最近 20 条用户/助手消息；每条最多显示 2500 字，隐藏会话、系统提示词、工具调用数据不展示。最多列出 100 个近期会话，完整历史仍在 Hermes 中查看。在“技能”按名称或目录搜索，点击阅读 SKILL.md，也可以打开技能目录。最多列出 200 个技能，单个文件最多显示前 128 KiB。读取当前运行目录中的资料，和右侧的备份快照数量可能不同；查看不修改 Hermes，也不把正文或标题写入管家任务结果。

需要新增或修正时点“添加”或“编辑”：

| 字段 | 怎么理解 |
| --- | --- |
| Hermes 运行目录 | Hermes 保存配置和资料的目录，不是管家程序目录 |
| Hermes 备份仓库 | 已有 Hermes 备份脚本和快照所在的仓库 |
| 工具 Python | 可以运行这套 Hermes 备份脚本的 Python |
| 受保护口令文件 | 已有加密备份口令文件的位置，只选文件，不填写内容 |
| Workspace | 可选，帮助登记其中的项目 |
| 启动程序和参数 | 可选，仅在需要从管家启动时填写 |
| 提交并推送 Git | 勾选后沿用原工具的远端推送配置；需要网络和已有 Git 登录 |

**恢复步骤：** “更多操作 → 校验备份” → 退出 Hermes → 点击“恢复备份” → 看预览 → 核对目标并确认。

本地 Hermes 的完整恢复可能把当前资料回到快照时的状态，包含替换会话；当前独有会话可能被移除。先保存现在的资料，再恢复旧版本。它不是“恢复演练”。

Hermes 原生快照保存在自己的备份仓库里，**不会出现在 `.amb` 备份列表**。需要恢复时回到本页。

## 4. 服务器 Hermes

**用来做什么：** 按需连接 Linux 服务器，检查网关、磁盘、内存和备份环境，创建或校验远端备份。

日常：选中服务器 → “检查状态” → 看右侧概览。连接成功、网关正常、备份环境就绪是不同的检查项；连接成功不代表已有可恢复备份。

**网关日志：** 点击同名按钮，通过现有 SSH 连接读取已登记网关服务最近 80 行 systemd 日志（最多显示末尾 40000 字）。按所选“系统服务 / 用户服务”范围读取；SSH 账号需要该服务的日志读取权限。查看窗口展示脱敏内容，不写入任务结果；服务名错误、权限不足或尚无日志时需核对“编辑”中的服务配置。此按钮仅查看，不重启网关。

设置只需在服务器变化时修改：

| 字段 | 怎么理解 |
| --- | --- |
| SSH 别名 / user@host、端口 | 连接到哪台服务器，默认端口 22 |
| SSH 登录账号 | 登录服务器的用户名；只有别名已配置用户名时才可留空 |
| 私钥文件 | 这台电脑已有的 SSH 私钥位置，不是备份口令 |
| SSH 配置、主机指纹文件 | 可沿用已有 config、known_hosts，确认连接的是正确服务器 |
| 远端 Hermes、备份仓库、知识库 | 服务器上的目录，不填写本机盘符 |
| 远端 Python、备份运行账号 | 服务器执行备份工具的环境和账号 |
| 网关服务名、服务范围 | 已有 systemd 网关的名称及系统/用户服务类型 |
| 远端口令文件 | 服务器已有的加密备份口令文件位置 |

“读取已有服务器连接参数”会填入已有环境中的公开连接参数，保存前仍需核对。登录账号漏填可能导致用本机用户名连接而失败。

**备份：** “检查状态”成功后点“立即备份”。**校验：** “更多操作 → 校验备份”。“更多操作”还提供已支持的网关启动、停止、重启和备份提交查看。

**恢复：** 校验 → “恢复备份” → 指定服务器上的新目录或空目录 → 看预览 → 确认。数据恢复后还需要检查运行环境、知识库位置和服务配置，再决定启用新网关；当前程序不替你完成生产环境切换。

服务器校验通过只说明快照文件完整，不能当作加密凭据已经解密验证。管家不会把远端备份自动下载成 `.amb`，也不会自动把本机 SSH 私钥复制到 U 盘。

## 5. 本地项目

**项目管理是本模块的主入口。** 它沿用你的项目规范：编号为 `P-YYYY-NNN-名称`；完整项目在工作区的 `projects`，归档在 `archive`；`agent/projects.json` 保存身份与路径。管家不会把项目状态复制到自己的另一张表中。

### 先选工作区

点“选择工作区…”，选择含 `agent/projects.json` 的工作区根目录。它不是某个项目文件夹，也不是 `myself` 笔记库本身。现有规范工作区直接读入；新工作区选择一个空文件夹后初始化。初始化只建立管理结构，不创建 Git 仓库或定时任务。

### 一键初始化项目

1. 点“新建项目”，填写名称和明确目标。
2. 默认建立 Obsidian 入口，让笔记库访问项目原件；无需入口可以取消勾选。
3. 点“一键初始化”。自动分配未用编号，创建 README、AGENTS 和 agent 下的 README、STATUS、TASKS、HANDOFF。
4. 新项目是“待开展”（candidate）；验收、负责人等未知信息先待补。源码、数据等业务目录按需要建立。

已有工作区的 `agent/templates` 模板会优先使用，新工作区使用管家内置的相同管理结构。编号一旦发出就永久保留；创建半途失败时保留现场，不盲目重复创建。

### 状态、任务和日志

选中项目，右侧有“当前状态、任务入口、日志与交接、项目笔记”四个页签：

- STATUS 是当前状态的唯一真源，生命周期可为 candidate、active、paused、completed、archived。
- TASKS 是唯一任务清单，或指向你已有的任务清单；不要另外复制一套任务。
- HANDOFF 保存历史日志和交接，按时间追加。

“编辑当前文档”可编辑 STATUS 或 TASKS；保留顶部 project_id。日志页使用“写日志 / 交接”追加真实结果、验证、未完成项和下一步，保留旧记录。若 TASKS 指向其他清单，实际任务仍在原清单维护。

### 与 Obsidian 配合使用

管家负责项目编号、初始化、状态导航、日志追加和归档；Obsidian 负责阅读、写笔记、链接材料与附件。两边使用同一份 Markdown 文件，编辑结果直接保存在项目内。

**第一次使用：** 先在 Obsidian 把工作区里的 `myself` 文件夹作为知识库打开一次。现有 `E:\obsidian\myself` 已是知识库，不必重新建立。新电脑需要安装并运行 Obsidian，重新打开该知识库；管家不安装插件或改写 `.obsidian` 配置。

日常操作：

1. 在管家选中项目，切到状态、任务或日志，点“Obsidian 中打开”。它通过项目已登记入口定位原文件；不会因中文、空格或同名笔记打开错误位置。
2. 写项目笔记时，切到“项目笔记” → “新建笔记” → 填名称。文件按需建立在真实项目的 `笔记/名称.md`，包含项目编号、草稿属性和状态、任务、日志链接。选中笔记，再点“Obsidian 中打开”写正文或添加图片、PDF 等附件。附件使用 Obsidian 现有设置，不另建全局附件规则。
3. 在 Obsidian 编辑后，管家监听所选项目的管理文件和笔记并刷新；切回管家也会重读。其他项目发生修改时，可点“刷新”。笔记原文只在窗口显示，不复制进管家的活动数据库。
4. “Obsidian 总览”打开现有项目索引，旁边的箭头可以打开归档索引。若你在 Obsidian 修改了 STATUS 的生命周期，用菜单里的“刷新 Obsidian 索引”重算生成区块；人工文字保留，状态以原 STATUS 为准。

已有业务笔记继续在原目录维护。“项目笔记”只列出项目 `笔记/` 下的 Markdown，不递归扫描全部业务材料，也不迁移旧笔记。TASKS 已指向其他清单时，继续维护原清单。

归档时笔记和附件随完整项目移动，已登记入口保持原名称并切换目标；重新启用后沿用同一份资料。归档历史在 Obsidian 仅供阅读，继续写入前先重新启用。Obsidian 本身仍是可编辑工具，管家不会替它锁住文件。

**没有入口或打不开：** 程序会提示知识库未打开、接口未注册、入口缺失或目标错误，不自动复制项目或覆盖入口。按旧规范明确不建入口的项目维持原策略；需要单独使用 Obsidian 时，可自行把真实项目文件夹作为独立知识库打开，再使用管家的打开按钮。

换电脑时，知识库与完整的 `projects`、`archive`、根目录 `agent` 都需要携带。目录联接/符号链接不保证随云盘、Git 或 U 盘复制自动迁移，也不保证外部正文被 Obsidian Sync 备份。先核对实际目标和登记表，再打开；错误入口会被管家拒绝。归档前停止 Obsidian、Agent 和编辑器对该项目的写入，避免旧标签页继续保存到旧位置。

联动采用 [Obsidian 官方 URI](https://help.obsidian.md/Extending+Obsidian/Obsidian+URI)，无需额外插件。现有联接方式及其同步限制见 [官方说明](https://help.obsidian.md/Files+and+folders/Symbolic+links+and+junctions)。

### 一键归档与重新启用

选中未归档项目 → “归档项目…” → 等待完整文件预检 → 填归档原因、交付和遗留事项 → 核对备份与旧路径，确认已经停止写入 → 点“归档项目”。

管家移动完整项目到 `archive`，保留编号，更新状态、目录入口、登记表和生成索引，并在 HANDOFF 追加记录。移动前后逐文件核对。索引里的人工文字保持原样，业务代码中的旧绝对路径不会自动改写。归档不等于项目验收完成，也不等于独立备份。

重新使用时，筛选“已归档” → 选中编号项目 → “重新启用…” → 写下一步并核对预检 → 确认。项目回到 `projects`，编号保留，状态改为 active，Obsidian 入口跟随更新。

旧的 `L-名称` 归档暂时只读，不直接重编号移动；正式开展新目标时创建编号项目并引用旧材料。归档内有目录联接/符号链接、目标冲突、跨文件系统或文件仍在变化时，程序停止预检。异常时保留 `agent/history/*-move.json` 和实际目录，按记录核对，不能反复点击重试。

同一工作区由一台电脑执行编号与移动；同步副本不要并发分配编号。管理锁与原 PowerShell 工具共用 `agent/.manage.lock`，遇到残留锁需要先核对进程，管家不会自动删除它。

### 资料备份与 Obsidian

**用来做什么：** 保存代码、未提交的工作文件、笔记及附件。

切到“资料备份与 Obsidian”页签，使用之前的备份操作。项目生命周期登记和备份登记用途不同：初始化不自动创建备份，需要时把完整项目目录添加到这里。

1. 点“添加”，选择项目或 Obsidian 类型。
2. 填一个好认的名称，选择要备份的整个文件夹。Obsidian 选择笔记库根目录。
3. “额外排除目录名”可以先留空；需要跳过大体积生成目录时再填写。
4. 保存登记，选中资料，点“立即备份”，设置备份口令。
5. 完成后查看提示的 `.amb` 文件位置。

普通项目和 Agent 资料备份不需要再配置 Python。备份前让编辑器、Obsidian 或其他程序停止写入资料。

**常用操作：** “更多操作 → 打开目录”；Obsidian 还可以“在 Obsidian 打开”。新电脑要安装 Obsidian 才能使用这个按钮。

建议备份完成后点“更多操作 → 试一次恢复（临时目录）”，或在备份页点“恢复演练”。演练通过会显示“已演练”。

恢复文件会放入新目录或空目录，原项目不会被覆盖。普通项目和 Agent 项目只备份工作文件，不检查 Git、不打包 `.git` 或提交历史。myself 继续使用自己的 Git 仓库；知识库编辑窗口里的“独立管理知识库 Git”只对明确启用的知识库生效。启用后 Git 历史另存为恢复目录中的历史文件，不自动拼接 `.git`。旧版本备份中的历史文件仍可恢复。

## 6. 其他 Agent

**用来做什么：** 保存 Codex、WorkBuddy、CodeBuddy、Claude Code 等的项目成果，以及机器上实际存在的聊天、配置和附件。

1. 点“添加工作 Agent”，选你使用的 Agent。
2. 如果还想保存项目成果，选择“项目文件夹”；只保存记录时可以不填。
3. 点“自动找记录目录”，核对找到的文件夹；找不到时点“添加目录”。可以登记多个。
4. 保存，点“检查状态”，确认目录存在。
5. 退出对应 Agent 或停止其写入，然后点“立即备份”。

选择项后，右侧概览列出会备份哪些资料，先核对范围，避免把同一大目录重复登记。

“浏览本地记录”可以查看支持的文本、Markdown、JSON 和 JSONL；直接点“搜索记录”可输入关键词搜索。数据库会备份，但不是每一种数据库都能直接在管家里阅读。

Agent 的 SQLite 数据库使用一致性快照；不同数据库之间没有联合快照保证，其他文件仍需停止写入。备份不会自动下载原应用仅存于云端的聊天。

换电脑后先通过管家恢复文件，再在原应用核对目录、版本和登录。**文件恢复成功不等于原应用可以直接续聊。** 有些会话依赖云端账号或原来的路径，需要从原应用导入或重新登录。

可选的“从管家启动 Agent”适用于配置好的非交互进程；交互式终端工具继续在终端运行即可。停止按钮只控制本次管家启动的进程，不会关闭你自己打开的 Codex 等应用。

## 7. 备份与迁移

### 专用 Agent 备份仓库

myself 保留自己的 Git 仓库；Hermes 沿用本地与服务器原有备份仓库。Codex、WorkBuddy、CodeBuddy、Claude Code 等的加密备份副本集中放在独立的私有 `agent-backups` 仓库，workspace 只登记位置。旧 workbench 源码保留，不作为这些备份的容器。

使用顺序：在“其他 Agent”点“立即备份” → 到“备份与换电脑”选择专用仓库 → 点“整理 Agent 备份”。会按 Agent 类型和资源编号分类复制已校验的 `.amb`，生成不含本机路径、聊天正文或口令的索引。旧备份若没有新的校验证据，请先在原资源页校验。重复整理不会重复复制，不删除 U 盘备份或仓库旧副本。

“整理”只更新本地仓库，需要用现有 Git 工具提交并推送私有远端；程序不会把项目仓库或 myself 当成 Agent 备份仓库。换电脑克隆 `agent-backups` 后，用“从备份文件恢复”选择 `archives/` 下的 `.amb`，输入单独保存的口令即可。

本版仓库单包限制 50 MiB，较大备份保留在便携 `backups`，直接用 U 盘携带。GitHub 对普通 Git 大文件有限制，见[官方说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)。备份口令、私钥、原始记录、个人资源配置不应加入仓库。便携程序移到其他电脑后，若仓库位置改变，再点“选择仓库”。

### 查看和恢复备份

**用来做什么：** 集中查看项目、Obsidian 和其他 Agent 的 `.amb` 备份。

`.amb` 是管家生成的加密备份文件。它携带文件及恢复登记信息，需要创建时的备份口令。列表中的名称、时间、文件数、大小和校验状态帮助你选对版本。

**试一次恢复：** 选一份备份 → “恢复演练” → 输入备份口令。管家恢复到临时目录并逐个比对文件，通过后清理临时目录。原项目不变，不会给原应用切换资料。

**正式恢复或换电脑：**

1. 点“恢复选中备份…”；外来的备份点“从备份文件恢复”。
2. 选择 `.amb`，输入创建它时的备份口令。
3. 选一个新的“恢复总文件夹”。多目录备份可以调整项目文件、记录等子文件夹名称。
4. 点“查看恢复清单”，确认名称、文件数、范围和目标。
5. 勾选确认，点“执行恢复”。非空目标会被拒绝。
6. 完成后资料会重新登记，在对应模块可以查看和打开。

换电脑不需要先导入资源配置，仅有 `.amb` 和正确口令也能恢复。恢复完成后请核对原应用的项目路径。

点“能恢复什么”查看范围与验证说明：恢复已备份的工作文件、记录、数据库与附件，自动登记新路径；不会安装原应用、下载云端聊天或保证所有客户端直接续聊。已通过新登记、新目录的图形界面恢复流程测试，核对中文文件、聊天文件、二进制附件和 SQLite 数据。原应用接续会话与生产服务器切换需要另外验证。详见 [恢复范围说明](RESTORE_SCOPE.md)。

“已校验”和“已演练”是针对那一份副本的结果。备份较旧时，应根据后来有没有修改资料决定是否重新备份。

## 8. 活动记录

**用来做什么：** 判断你点的操作做完没有，找到失败原因。

选中一条任务，下方看结果和脱敏日志。状态“已完成”表示该操作结束；例如“检查状态”完成，不代表已经创建了备份。

“请求取消选中任务”会在安全检查点停止，关键恢复写入期间可能需要等待。网络中断时先检查服务器实际结果再重试，避免把“没有收到结果”当作“远端肯定没执行”。

旧的失败记录会保留，后续成功不会删除旧记录。工作台“需要你处理”只依据每项资料最新一次任务判断失败；查看时结合时间与实际情况。

搜索和浏览得到的聊天内容不写入管家任务历史。

## 9. 设置

日常只看“备份放在哪里”。默认是程序旁的 `backups` 文件夹，适合 U 盘携带，通常无需修改。

- “打开备份文件夹”：查看已经保存的备份。
- “更改位置”：选择新文件夹后立即保存，不需要再点保存按钮。
- 更换位置不会搬走旧备份；旧文件仍在原目录，可以用“从备份文件恢复”选择。

“其他功能（需要时再打开）”默认收起，里面才有下面的选项：

| 选项 | 怎么用 |
| --- | --- |
| 自动备份保留数量 | 默认 10 份。修改后保存。自动备份成功且校验通过后，清理可确认的旧 .amb 版本，也可能包含手动创建的旧副本 |
| 记住备份密码 | 可选。第一次设置至少 8 个字符的“总密码”；它保护保存的各项备份密码。关闭管家后锁定，下次需要输入总密码解锁 |
| 登记清单导入导出 | 只保存资源名称和路径，不包含项目文件、聊天或密钥。导入只合并新登记项，换电脑仍需核对路径 |
| 运行环境检查、打开管家数据目录 | 排查问题时再使用 |

**不想记住密码：** 保持默认，备份和恢复时手动输入即可。备份密码用于解密那份 .amb；总密码只用于打开密码记忆库，两者不同。SSH 私钥与 Hermes 原生密码文件继续沿用原有材料。请独立保管密码，程序无法找回忘记的密码。

**开启自动备份：** 到某项资料的“编辑”中勾选，需要已保存且当前可用的备份密码。管家打开期间约每天执行一次，发现对应 Agent 运行时延后。服务器当前采用手动备份。

## 10. U 盘与换电脑

Windows 便携版，把**整个 `AgentManager-Portable` 文件夹**复制到 U 盘，不要只复制 exe。

| 内容 | 作用 |
| --- | --- |
| `AgentManager.exe`、`_internal` | 程序及运行组件 |
| `portable.json` | 告诉程序在自身目录保存数据 |
| `data` | 登记配置、活动记录、可选密码记忆库，以及 `asset-library` 通用技能与提示词库 |
| `backups` | 管家创建的 `.amb` 备份 |
| `restored` | 如果使用默认恢复位置，放恢复出来的资料 |

复制前关闭管家，完成后再安全拔出 U 盘。程序内部路径会跟随目录位置和盘符变化；原来位于电脑硬盘的项目、Obsidian、Hermes、SSH 文件不会自动随程序带走。

在另一台 Windows 电脑上：打开管家 → 需要时解锁口令库 → 恢复资料 → 编辑登记路径 → 检查状态。若备份保存位置改到了程序外，也需要单独带走对应备份。

macOS 或 Linux 要使用对应系统的包。Windows exe 不能直接在它们上运行，但 `.amb` 备份格式可跨平台恢复；路径和原应用需要重新配置。Hermes 原生备份需要另外携带或取得对应备份仓库，不能只带 `backups` 文件夹。

更新程序前关闭管家、留一份完整目录副本；替换运行组件时保留原 `data`、`backups` 和恢复资料。

## 11. 常见问题

**添加了资料，为什么还显示未备份？** 登记只记录位置，请再点“立即备份”。

**为什么查到 Agent 在运行，却不知道它在做什么？** 当前检测的是进程，不是任务内容。要知道等待输入或正在处理什么，需要原应用提供任务事件，当前没有接入。

**为什么有些聊天搜不到？** 记录可能不在登记目录、仅在云端，或格式还不支持。当前搜索每次最多读取 300 个文件、32 MiB，并限制结果数量；Hermes 目前搜索会话标题。

**为什么恢复说目标非空？** 请选择新文件夹，先恢复并检查，之后再由你决定如何放回原应用。

**换电脑后服务器连接失败？** 核对 SSH 登录账号、私钥位置、配置及可信主机指纹。U 盘里的配置不会携带原电脑的 SSH 私钥。

**为什么自动备份没有运行？** 确认已为该项开启、管家正打开、口令已保存且口令库已解锁；对应 Agent 运行时会延后。查看活动记录可核对实际执行情况。

**旧 Hermes Workbench 可以移除吗？** 管家独立运行，已迁入状态、资料保护、诊断和活动汇总。旧 Workbench 的实时对话、模型配置与上下文统计暂未迁入；如果你还用这些功能，可以先保留它。

## 12. 技能与工具

这是独立模块，分“技能（Skills）”“MCP（外部工具）”“提示词”三个页签。自动读取已登记的本地 Hermes 和其他 Agent 目录；按来源筛选或按名称搜索。没有找到时可以添加自己的技能目录或 MCP 配置文件。只读取本地文件，不自动联网下载、运行脚本或启用连接。

### 技能（Skills）

1. 选中技能，右侧阅读 SKILL.md，下面可以复制显示内容或打开目录。
2. “导入技能”：选一个直接包含 SKILL.md 的文件夹，复制到管家的通用库，原目录保留。
3. “复制技能给 Agent”：先选技能，再选择登记的 Agent 技能目录，或手动选择目标 skills 文件夹。程序复制技能正文、脚本和附件，不执行它们。

同名目标不会被覆盖；链接、超出限制或正在变化的文件会被拒绝。单个技能限 1000 个文件、1000 个目录、20 MiB、8 层。不同 Agent 的技能约定可能不同，复制后在原应用确认支持情况。

### MCP（外部工具）

MCP 配置让 Agent 连接外部工具。管家读取 JSON、TOML、YAML 中的 mcpServers / mcp_servers，展示名称、连接类型、主机、命令名称、环境变量名称和启用状态。参数、密码值、授权头和带凭据的完整 URL 不展示。

本版提供清单查看与“打开所在目录”，不自动修改原配置、安装依赖或启用 MCP。需要改动时在原 Agent 的设置或原文件中处理，再刷新。这避免不同客户端配置格式互相影响。

### 提示词

“新建提示词”保存常用工作要求到通用库；选中后可复制内容到任意 Agent。“编辑提示词”只修改管家通用库里的文件。原 Agent 的 AGENTS.md、CLAUDE.md、SOUL.md 等只供查看，避免改变项目规范；它们的内容不会保存到活动记录。

### 携带与备份

自有通用库在 `data/asset-library`，随整个便携目录携带。“备份通用库”会登记它并使用现有加密备份流程，输入备份密码后生成 .amb。恢复到新目录后可以查看、再导入需要的技能或新建提示词，不自动覆盖现有通用库。外部 Agent 的原文件不因登记来源而自动带走，需要在其他 Agent 中备份对应目录。

“管理自选来源”只移除你添加的目录或配置文件登记，不删除文件。预览单文件限 1 MiB、最多显示 40000 字；清单有数量与深度限制，完整内容仍可在原目录查看。

设计参考 [Skills Manager](https://github.com/xingkongliang/skills-manager) 的统一资料库与按 Agent 查看方式，本项目沿用原有 PySide6 和加密备份，没有引入其应用框架。
