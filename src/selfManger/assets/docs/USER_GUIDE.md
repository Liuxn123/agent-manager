# selfManger v1.0.1 使用说明

## 1. 先看这里

selfManger是每天开始 Agent 工作的个人工作台。先看今天做什么，再进入项目，找到 Agent 与资源；需要备份时进入数据安全。

侧栏顺序为今日工作台、计划管理、项目管理、知识库、数据安全和设置。Agent 管理模块暂不提供；Agent 备份与恢复仍在数据安全中操作。电脑与环境入口已移除；工具整合入口已移除，知识库不展示旧资源记录。


建议先在“项目”选择自己的规范工作区，再在“工作台”写今天的计划。没有工作区也能先写每日计划和收藏资源。

## 2. 工作台

默认显示今天。工作台不会因 Obsidian 文件变化、切回窗口或定时轮询而自动重读；外部修改 Markdown 后点顶部“刷新”。程序内添加、编辑和勾选任务后仍会立即更新。任务区只保留“今日要做”和 Todo：“今日要做”显示正在查看日期的任务，可直接勾选；Todo 可选截止日期，列表显示其他日期尚未完成的任务，双击后进入对应日期。顶部日期框可以选择过去或未来，左右箭头切换一天，“回到今天”返回。项目与备份状态仍表示当前状态。

点“日程总览”，选择以下范围：

- **未来 30 天**：含今天的未来安排与未完成任务。
- **所有未完成任务**：也包括过去日期仍没完成的任务。标注“未完成（过去日期）”，不会自动挪到今天。
- **全部已登记日程**：跨日期查看已有安排；勾选“显示已完成任务”可回顾完成记录。
- **自选日期范围**：选择开始、结束日期，查看某一周、某个月或更远的计划。

双击事项或选中后点“打开所选日期”，进入该日期查看或编辑任务。任务和日程现在保存在统一 SQLite 任务库，计划、工作台和关联项目显示的是同一条记录；日期可留空，留空时显示在“待排期”。日期精确到天，不记录小时段。新建或编辑项目任务时可关联项目，来源可标记为 AI 规划或手动编写。

首次启动时，程序会把已存在的每日 Markdown 任务/日程和已登记项目的 TASKS 清单导入 SQLite。导入只执行一次并保留原 Markdown；后续新增、修改或完成状态以 SQLite 为准，直接在旧 Markdown 中改动不会自动同步。新增日期文件和新登记项目可在启动/进入相关页面时补充导入；不会扫描其他项目正文或 Agent 对话。

计划首页的“添加安排”会创建长期安排，至少填写开始日期或目标日期之一，并保存到“计划/安排”Markdown。日计划只写对应日期的任务和日程；周期任务按规则投影显示，不复制到每日文档，完成状态保存在周期计划记录中。日计划里的每日任务和日程可切换状态或删除，删除前会确认且只移除该条。目标可在计划管理中编辑，其他计划记录使用应用内编辑弹窗。时间线的“查看全部”展示所有带日期的长期计划。日程列表、目标与计划、项目时间线不再另设页面。今天提醒显示未完成的周期任务、目标到期项及每日任务的截止 / 逾期事项。

顶部四张卡片显示今日任务完成数、进行中项目、运行中的 Agent 和到期提醒数。每日任务状态取自统一 SQLite 任务库，周期任务的状态取自周期计划记录。空白计划显示引导，统计不使用演示数字。

工作台的环图显示所选日期的任务完成情况，以及当前已加载、未归档项目的状态分布；周期任务仍计入提醒。图表与页面一起刷新，没有数据时显示引导。浅色和深色主题均可查看具体数量。

日常点“添加任务”或“添加日程”使用统一表单。可设置日期、关联项目/目标编号、优先级、状态、AI/手动来源及备注；保存后会在工作台、计划和所关联项目中同步显示。目标关联任务后，目标进度按已完成任务数自动计算；没有关联任务时显示目标文档中原有的进度值。原 Markdown 文件保留作为导入前记录，不再作为导入后任务的实时数据源。

工作台“今日要做”、Todo、计划日视图和项目任务卡读取同一批 SQLite 任务。点复选框或选择状态可以更新同一记录；双击任务可编辑。没有日期的任务进入“待排期”，不会自动挪到今天。

小窗口减少装饰并保留双栏，页面可滚动，长项目说明省略并可悬停查看全文。

项目卡片展示真实阶段与下一步；双击继续。最近工作表示最近从管家进入的项目。资料保护展示已记录的备份结果，不代表当前 Agent 或服务器已在线。点备份卡片进入对应数据安全登记。

点“编辑今日计划”，使用这个格式：

```markdown
# 2026-10-05

## 日程
- 09:00 selfManger开发
- 14:00 Hermes 测试

## 今日任务
- [ ] 测试恢复
- [ ] 完成阶段总结
- [ ] [高] 核对恢复结果 @10:00

## 工作记录
今天发现的问题可以记在这里。
```

日程是普通时间文字，不发送通知、不连接日历服务。任务可以直接勾选，程序写入 `[x]`；普通 `- 任务` 也能显示和勾选。其他 Markdown 内容保留。

点“Obsidian 中打开”编辑原文件。外部编辑或原子保存后自动刷新，程序重新获得焦点也会刷新。若编辑期间原文件改变，保存会停止，原文件不会被覆盖。

双击需要继续的项目进入项目。最近工作仅表示你从今日进入过的项目，不推测 Agent 对话内容。暂停项目与最近操作失败 / 中断显示在“需要我处理”；双击进入对应页面。旧版工作笔记仍可从页底查看。

午夜后首页会切换到新一天。新文件在第一次保存计划时创建，程序启动不会批量写入知识库。

## 3. 项目

选择包含 `agent/projects.json` 的工作区根目录；普通项目目录不是规范工作区。也可选择空目录初始化，随后点“新建项目”。编号按既有规范分配且不复用。

新建项目时分别填写项目名称和英文目录名。项目名称用于界面、索引与 Markdown 标题；英文目录名用于 `projects/<编号>-<目录名>` 与 Obsidian 入口，保存时只保留英文/数字并转换为小写连字符格式，避免空格、中文和文件系统保留字符影响路径。点“翻译为英文”会将项目名称发送至 Google 翻译并填入目录名；也可手工编辑。在线翻译不可用时不会阻止创建，只需填写英文目录名。

新建窗口按“项目信息 → 开发规范 → 技能与资料（可选）→ 确认创建”四步完成，通过上一步/下一步返回修改，仅在最后一步显示“创建项目”。内置只保留通用项目模板，可编辑规范，或用“选择规范 Markdown”载入自己的规范；规范追加到项目 AGENTS.md，工作区原有管理模板内容保留。“导入 JSON 模板”可加载自定义规范和项目内文本文件；“另存为模板”将当前规范及附加文件保存到新的 JSON 文件，不包含本机 Skills/知识选择，便于复用。模板格式和代码改动分析见源码仓库 `docs/PROJECT_INITIALIZATION.md`。

Skills 可显式从已登记本机 Agent 的已有目录发现，或手动选择含 SKILL.md 的目录；知识资源复用已加载索引，也可刷新索引或选择本地文件。全部以勾选为准。Skills 连同脚本、资源和空目录完整复制到项目 `.selfManger/skills/<技能目录名>/`；知识资料继续保留引用，原始技能与资料不改动。初始化将选择及副本位置写入 `.selfManger/config.json`，在 `.selfManger/RESOURCES.md` 中说明，并从 AGENTS 提供各技能 SKILL.md 入口；不执行技能脚本、不修改全局 Agent 原生规则，也不自动向模型发送知识内容。Agent 是否加载某个 Skill 必须依据该 Agent 的实际规则确认，不能仅凭配置中的记录判断。

“确认创建”用项目名称、目标、保存位置、所选规范、要复制的技能和关联资料说明创建结果，不再直接展示配置或 Markdown 源文。最终编号在创建时分配；非法模板、技能同名、失效来源和技能树中的链接会在分配编号前拒绝。项目内技能副本可随项目迁移；知识引用与原始技能来源记录尽量保存为相对路径，跨盘保留绝对路径，迁移后需核对。复制中发现来源变化或目标冲突会停止并保留现场，不覆盖已有文件。模板不能覆盖基础管理文档、Agent 私有配置和隐藏目录，不运行任何模板脚本。本阶段只改新建项目，已有项目不会自动迁移，记忆和开发会话功能尚未加入。

创建成功后会打开“项目 AI 提示词”，默认选择“新项目初始化”，可预览并复制给 AI，同时附上具体需求。新项目的 `agent/PROMPTS.md` 保存初始化和后续接手两份提示词，`agent/README.md` 提供入口，项目规则补充每轮任务的汇报约定。工作区已有自定义模板时保留其内容，仅在缺失时追加规则和提示词导航，不改写模板源文件。

已有项目可在“Agent 文档 → AI 提示词”查看并复制“已有项目接手”提示词，无需重建项目或覆盖原文。AI 应在开始时说明当前阶段、本轮目标与验收条件；实质任务收尾时更新 STATUS、TASKS 指定的任务真源，并追加 HANDOFF，项目动态读取交接记录。回复需说明完成内容、实际验证、未验证事项和下一步；纯问答无需制造日志。任务文档在外部编辑后需点击“同步任务文档”载入应用，里程碑仍由用户维护。归档或状态异常项目暂不可从该入口接手。提示词只提供约定，应用不会自动调用 AI 或保证外部助手执行。

左侧点项目卡片，右侧封面区展示项目名称和“项目介绍”。介绍由你通过“编辑介绍”编写并保存到 `agent/projects.json`，与 STATUS 的阶段、进展和下一步分开；留空会显示编辑提示。每个介绍最多 4000 个字符。项目页默认显示进行中项目，可切换到已归档；选择项目时会记录最近使用时间，进行中项目按最近使用顺序排列。旧状态中的非归档项目会在列表中统一显示为“进行中”；归档后重新启用也会回到进行中。工作区路径可通过右侧“⋯”维护菜单切换。归档会更新 STATUS 并从 Obsidian `03-项目`目录中移除登记的项目目录联接，真实项目目录和登记路径保留；重新启用会恢复该联接。永久删除只对已归档项目开放，点击“删除项目”后需准确输入完整项目名称。删除会清除项目目录和仍存在的登记 Obsidian 入口，已发编号仍保留；统一任务、计划与资源记录不会自动删除。执行前请核对项目引用和备份。

“概览”按项目仪表盘展示近期任务、项目信息、项目资料、关联资源和最近动态。“项目资料”卡与“文档”标签用于管理你维护的文件：上传对话框支持一次选择多个文件，副本会逐个复制到当前项目的 `文档/` 目录，原文件不移动、不修改；遇到同名文件会拒绝覆盖，并在批量上传结果中列出未复制的文件。可选择文件预览，双击或点击“打开所选文件”使用系统关联程序打开；Markdown 可交给 Obsidian 编辑，也可打开资料目录自行整理。Agent 的 STATUS、TASKS、HANDOFF 等管理文件单独放在“Agent 文档”标签，避免与项目资料混在一起。任务卡和“任务”标签读取统一 SQLite 任务库；任务页可直接编辑任务，也可分别打开 AI 规划和手动编写 Markdown 清单。编辑 Markdown 后点“同步任务文档”，变更会写入 SQLite，工作台和计划页随之读取同一记录。首次导入的 TASKS.md 保留原样，不会被新清单覆盖。统计只从当前项目的任务库、资源库关联条目和 HANDOFF 读取；没有来源的数据会显示未设置或空状态。负责人、成员、起止日期、优先级和仓库地址可从概览“项目信息”卡编辑，保存在 projects.json 的可选字段中。

“任务”标签分成 AI 规划和手动编写两张卡片，各自对应 `agent/TASKS-AI.md` 与 `agent/TASKS-MANUAL.md`。可在应用内选中任务并编辑，也可用“打开文档”交给 Obsidian；新增 Markdown 行时 ID 填 `new`，然后回到应用点“同步任务文档”。保留已有 ID 才能让修改更新原记录；从文档移除一行不会删除 SQLite 任务。AI 规划任务在概览卡中仅作只读展示，不再提供“交给 AI”或“重新交给 AI”按钮；已有的已完成状态和完成记录会显示在列表中，其他状态不会被自动改成已完成。AI 任务不能通过复选框、编辑器或同步 Markdown 手动标记完成；手动编写任务仍按原方式勾选完成。项目助手的 `agent/TASKS.md` 原文独立保留为原始执行清单，不会被这两份文件覆盖。“Agent 文档”标签收纳 STATUS、HANDOFF 和阶段总结预览。阶段和下一步由你在 STATUS 中维护，日志与阶段总结由你在 HANDOFF 中维护。“资源”标签只显示资源库条目；要关联资源，可在资源库条目的“适用项目”中填写项目编号。Agent 标签只显示 STATUS 中明确关联的 Agent 编号。

“近期任务”分开展示 AI 规划与手动编写的任务。“清单任务”统计两类任务的总数。首次从旧 `TASKS.md` 导入的项目清单按其标题分类并保留原文件；此后应用任务数据以 SQLite 为准，并由两份专用 Markdown 文档分别编辑和同步。

日志数来自 HANDOFF 中按日期追加的记录，包含阶段总结；最近更新来自 STATUS 的 updated 字段，不代表 Agent 在线。关联资源数只统计项目资源标签中能找到的资源库条目；找不到的资源引用仍会保留并提示。项目资源标签不显示 Agent。

标签入口：概览、任务、文档、笔记、资源、Agent、设置。“笔记”页提供当前项目“笔记”目录入口。首次使用时先在设置中选择包含 `.obsidian` 配置目录的 Obsidian 知识库根目录并保存；之后点“打开项目笔记目录”会通过 Obsidian 打开工作区中的对应笔记目录。目录不存在时会先在项目中创建，仍由你直接编写 Markdown 笔记。若提示知识库与项目入口不匹配，请选择正确的知识库根目录或检查项目登记中的 Obsidian 入口。

STATUS 是项目进度真源，HANDOFF 按日期追加日志。应用任务统一保存在 SQLite；AI 与手动任务的专用 Markdown 文档可从项目“任务”标签同步。原 TASKS.md 保留为旧执行清单，不会被新任务文档覆盖。

需要修改 STATUS 或 HANDOFF 时，在项目对应标签点击“在 Obsidian 中编辑”维护原文件。任务请在项目“任务”标签打开 AI 或手动清单，并按提示同步。项目笔记保存在真实“笔记”目录，Obsidian 与管家共用。进入项目时读取一次；外部修改后点左侧“刷新”，Markdown 预览与任务统计一起重读。项目页不按文件变化或窗口切回自动刷新。

项目标题旁的 Git 按钮可查看状态，并在详情中暂存全部变更、提交已暂存文件、快进拉取和推送。尚无仓库时可在项目目录初始化；如项目登记了仓库地址，会添加为 `origin`。暂存全部会先确认；提交需要填写说明；拉取只允许快进，遇到分叉时会停止并提示。项目目录包含多个仓库时可选择目标仓库。HTTPS 远程可在“设置”保存访问令牌，SSH 远程使用本机 SSH 密钥/ssh-agent。标准模式将令牌存入系统凭据库，便携模式存入加密口令库；令牌不写入项目设置、远程 URL 或日志。未设置 Git 提交者姓名/邮箱时，需先按 Git 提示配置。归档会把 STATUS.md 的生命周期改成“archived”，并暂时移除 `03-项目`中的项目目录联接；不会搬动或删除 `projects/`中的项目文件夹。重新启用会在登记的原路径重建联接。“项目总览”和“归档项目索引”按状态分类。旧 `L-` 项目也可直接切换状态和继续维护。归档不等于备份。

## 4. 阶段总结

阶段总结直接由你编写并追加到项目 `agent/HANDOFF.md`，使用“日志”标签和“在 Obsidian 中编辑”打开原文件。

记录时区分已完成和待验证的内容，并保留原有交接记录。

需要借助 Agent 整理时，可自行复制项目状态和任务内容到常用 Agent；管家不会自动发起 AI 调用。

原 HANDOFF、日志和阶段总结共用同一份 Markdown，不额外生成 SUMMARY / PROGRESS / REFLECTION 文件。

资源关联只通过资源库条目的“适用项目”维护，项目资源标签只展示对应资源库条目，不展示 Agent。STATUS 中原有的 Agent 引用保持不变。失去登记的资源编号保留并提示未找到，程序不会擅自删除引用。

## 5. Agent

Agent 管理模块暂未实现。Agent 备份、校验和恢复统一从“数据安全”页面操作。


## 6. 知识库

页面顶部集中搜索、快速收集、刷新索引和打开根目录；两个图标按钮可悬停查看说明。空库以插画和收集/新建专题入口引导，不显示空统计、无用分页和未选择的详情。空主题可直接“添加到此专题”；没有配置 Vault 时可从引导进入设置。

有资料时，宽窗口可同时浏览资源和预览，点“收起预览”扩展列表；窄窗口先显示列表，选择资料后点“预览”，再用“返回资料列表”回到原筛选与选择。列表上方的“资料构成 · 全库”仅在全部资源且没有额外筛选时显示，统计活跃笔记、网页、文件与组合，排除归档、回收站和文件夹。组合按一个资源统计，刷新索引后更新。

知识库以设置中的 Obsidian Vault（myself）为真实存储基础，以主题和资源展示内容。默认使用紧凑卡片，支持切换语义列表；卡片显示标题、用途或原文摘录、类型和标签，路径/大小/修改时间只放在详情的位置页。左侧学习与研究、开发与技术、AI与Agent、素材与参考、生活与个人和归档来自真实目录，选择主题后汇总全部子专题资源。收集箱、最近使用、收藏和项目资料是快捷视图。资源列表上方会持续显示当前保存位置，可直接打开对应文件夹；主题资源实际保存在 Vault 的 `02-知识/<专题名>/` 目录。

点击“快速收集”将链接、文件或笔记暂存到 `02-知识/00-收件箱`；左侧“收集箱”显示待整理数量，可多选后用“归类所选”移动到知识主题。收件箱是快捷视图，不重复显示为一个主题。主题资源实际保存在 Vault 的 `02-知识/<专题名>/` 目录；选中主题后，页面顶部出现“添加到此主题”，可在该主题直接收集链接、文件或笔记，空主题也会展示它对应的实际文件路径。底部输入框可直接收集链接或快速笔记到当前主题；全局视图默认放入 `02-知识`。多文件收集默认在目标主题/收件箱下创建同名实体文件夹；资源列表右键也可将多项资料整理进当前主题下的新文件夹，操作会移动原件并更新索引。单项“整理到专题”同样移动原件。目标只允许选择 `02-知识` 内的目录，名称冲突会提示，不覆盖文件。索引刷新统一使用页面顶部按钮。文件支持多选/拖入，并明确选择引用原件或复制；收集时原件不移动，同名文件不覆盖。网址保存为 .url，笔记为 .md，外部引用为 .kref；引用归类只移动 Vault 内的 .kref 登记文件，不移动 Vault 外原件。

用途、个人记录、标签、关联资料以及项目/Agent 关联在“编辑资料信息”中统一维护；关联资料可直接点击阅读。最近使用只记录实际打开或编辑，不用文件修改时间冒充使用记录。支持标题/标签/用途/个人记录/受限正文搜索、标签筛选、类型筛选、分页和排序。主题支持重命名、删除空目录及上移/下移，顺序保存在 Vault 的知识库索引中；移动资源会同步更新路径及元数据。

详情区“在 Obsidian 中打开”会通过 Obsidian 打开 Vault 内原件，“打开文件夹”会打开原件所在目录；Vault 外的外部引用不能在 Obsidian 中打开，可从文件夹查看位置。详情下方可将资源归档，或移入回收站；归档会将 Vault 内原件移动到 `98-归档` 并记录原位置，恢复时移回；旧版仅标记归档的项目会显示“整理到归档”以完成迁移；回收站只标记状态，原始文件保留。归档后原主题目录中的空子目录会清理，空主题可删除。资源元数据保存在 99-系统/知识库索引/资源/*.json，SQLite 仅保存扫描缓存和兼容索引，文件本体不存数据库；换电脑时将这些记录随 Vault 一起迁移。原 Markdown frontmatter 中的标题/标签会被读取，历史原文不批量改写。扫描跳过隐藏目录、凭据、系统规则、日记和项目联接，不递归导入项目源码。最多索引 20,000 文件、12 层目录，每页 200 项；正文读取有总量与单文件上限。原件无法访问时仍保留失效记录。Markdown 编辑会检查外部修改，保留 UTF-8 BOM 和换行格式。

项目和 Agent 页面仍可进入对应的关联资源视图；既有项目正文保持在项目工作区。侧栏前四项固定为今日工作台、计划管理、项目管理、知识库，没有工具整合模块。

### 整个目录与多文件资源

一条资源可以是独立文件，也可以包含整个 Skill 目录、课程笔记或多份文件/链接。“收集资源”支持整个目录引用；多文件默认组成一条资源，也可分别添加，或加入已有资源。拖入一个目录可直接登记整体资源。原文件不移动，目录内部结构保留。

已有零散资料可 Ctrl 多选后在右键菜单中选择“整理到新文件夹…”，在当前主题下创建实体文件夹并将原件移动进去；若只需归类单项，可选择“整理到专题…”。历史资料合集仍可浏览，移动目录型合集会移动原目录。

搜索会检索内部文件的标题、标签与受限正文，并在资源结果中标明命中的文档，选择结果会预览第一个命中项。主列表按资源计数，内部内容不重复铺开；状态栏另显示内容总数。只有目录首页实际包含 SKILL.md 才标为 Skill；Skill 使用教程是普通笔记。

资源组保存于 99-系统/知识库索引/资源组/*.json，记录目录/成员、首页、排除项和逻辑主题；既有元数据文件继续随 Vault 迁移。外部目录失效时资源登记仍保留。嵌套目录整体登记后，内部包不重复显示为顶层条目。

## 设置

“Git HTTPS 访问令牌”用于 GitHub / GitLab 等 HTTPS 仓库的认证，保存在系统凭据库；便携模式保存在加密口令库，需先解锁。SSH 仓库直接使用本机 SSH 密钥或 ssh-agent。移除令牌不会影响 SSH 操作。

设置页可选择浅色或深色外观，选择会保存在本机并在下次启动时恢复。其他设置用于管理 Markdown 资料目录、统一备份位置、统一备份口令、保留数量和维护工具。统一备份口令保存在系统凭据库；便携模式保存在加密口令库中，需先解锁。设置页口令框默认隐藏，点击“显示”可随时查看，也可移除已保存口令。备份位置可选本机网盘客户端正在同步的目录；管家只写入本机目录，实际云端同步由网盘客户端负责。更改位置只影响之后创建的 `.amb`，不会自动搬移旧备份。

## 7. 数据安全

数据安全采用左右布局：左侧“我的资料”列出已登记且支持备份的资料，可按名称搜索。可添加本地文件夹、项目、Obsidian 资料库、Agent、脚本备份和 Hermes。文件夹、项目、资料库、Agent 和脚本输出均归档为压缩并加密的 `.amb`，统一保存到设置中的备份位置；每个新版本按资料名与版本时间分层，版本目录中包含归档和元数据，旧版散放备份仍可识别。备份版本列表可选中单个版本并确认删除；删除操作只删除所选归档及元数据，不删除原始资料或其他版本。Hermes 继续调用原生备份仓库与恢复工具。脚本自动备份在登记时可启用；脚本执行时会收到 `SELFMANGER_BACKUP_OUTPUT_DIR` 环境变量，必须将要归档的文件写入该临时目录。支持 Python、PowerShell、批处理和 Bash 脚本。请勿把口令或访问令牌写入脚本参数。网盘备份通过把统一备份位置设置为本机同步目录实现。

右侧“保护概览”展示当前资料的最近备份、内容校验、恢复演练、可见版本数，以及资料与备份位置；“备份版本”与左侧所选资料联动，切换页签不必重复选择资料。刷新保留所选资料与仍存在的备份版本。窄窗口的操作按钮自动换行，详情区可纵向滚动。选择版本并点击“继续恢复检查”后，程序沿用原有解锁、内容检查和恢复预览流程。项目、资料库与 Agent 备份默认恢复到新目录，不直接覆盖原件；Hermes 使用原生恢复流程，完整恢复可能影响当前运行资料，执行前需检查预览。没有可用版本或资料正忙时，继续按钮不可用。

状态只覆盖登记范围和本地可读取到的备份；不会备份云端独有内容、应用账号或安装环境。脚本由用户配置并在本机运行；自动备份仅在管家运行时按每日计划执行。旧的目录变更追踪配置和记录仍保留在本机数据库，但当前页面不再显示该功能。
## 8. Obsidian 联动

项目使用原登记的入口联接或独立 Vault 策略；不复制项目正文。归档项目会从 Obsidian `03-项目`目录中隐藏入口，取消归档后在原路径恢复联接；联接始终指向 `projects/`中的同一份实际资料。

每日与资源默认放在 `工作区/myself/selfManger`。没有项目工作区时使用 `管家数据/工作台`；设置能选择 Obsidian Vault 内另一个文件夹。

若提示没有知识库，先在 Obsidian 把该文件夹的上级作为 Vault 打开。管家不创建或改写 `.obsidian` 配置。未保存的今日计划还没有文件，先保存一次再打开。

改资料位置不会搬迁旧文件；把旧每日 / 资源文件夹人工复制到新位置，确认后再选择。项目规范仍由原工作区决定。

## 9. 设置

设置页把资料目录、备份目录、统一备份密码和可选维护分成独立卡片，右侧汇总运行模式、目录连接与密码状态。修改资料或备份目录只影响后续文件，不会自动搬迁旧资料。

常用设置只有文字资料位置和备份位置。默认通常可以直接使用。

选择文字资料位置时，推荐选择自己的 Obsidian 知识库内的专用文件夹。如果想随 U 盘带走，选择便携程序目录内的资料文件夹。

更改备份目录只影响以后创建的备份，不搬动旧副本。高级区域调整自动备份保留数；只有新备份成功且旧副本可验证时才清理。电脑维护中的配置导入导出只包含登记和程序设置，不包含项目正文、聊天、备份密码或 SSH 私钥。

## 10. U 盘与换电脑

保留 `portable.json` 和整个便携目录，包括 exe、_internal、data、backups，以及你放在其中的文字资料。不要在移动或升级时只复制 exe。

目录内的 SQLite 配置路径随目录或盘符变化，原 .amb 格式继续兼容。目录外的 Obsidian、项目、记录、私钥或 Hermes 仓库不会自动装进 U 盘，换电脑需要携带、恢复或重新选择。

本版升级只新增工作台配置标记，不改旧项目、Agent id、备份格式或原笔记。旧 projects.json、STATUS、TASKS、HANDOFF、笔记、登记、备份和设置继续使用。

重要文字资料也要保护：可在数据安全登记工作台资料文件夹为项目 / Obsidian 备份；若它在 myself 内，myself 完整备份会包含它。程序配置导出不代替正文备份。

先恢复资料，再安装目标 Agent 的运行环境、核对登录与实际数据位置。记录能浏览，不代表原应用一定能直接续聊；跨系统路径或登录材料也可能需要手工处理。Hermes 使用独立原生恢复入口。

## 11. 常见问题

**项目列表为空：**点项目标题栏右侧“⋯”→“切换工作区…”选择包含 agent/projects.json 的工作区根目录；这不会删除或重建项目。进行中 / 已归档视图和搜索条件也会影响列表。源码和便携版可使用不同数据目录，设置中的数据位置用于核对。Windows start.cmd 在相邻 selfManger-Portable 已安装时沿用它的数据；SELFMANGER_DATA_DIR 仍可指定隔离数据。

**资料看起来消失：**点知识库筛选栏的“×”清除搜索、类型和项目 / Agent 筛选，或从“全部文件”重新浏览。搜索覆盖全部已索引资料，当前列表每页最多显示 200 项；新建资料会继承当前项目 / Agent 关联。

**项目文档不完整：**详情显示缺失或不可读的文档，其他资料仍能查看。打开项目文件夹检查；管家不会用模板覆盖个人原文。


**能提前安排日程吗？** 可以。添加时选择日期，或用“日程总览”查看跨日期计划。日程由 Markdown 保存；本版不接外部日历服务，MCP 仅登记用途与配置说明。

**项目总结由哪里维护？** 阶段总结直接写入已有 HANDOFF，避免进度、总结、交接多份正文互相冲突。

**为什么保存提示文件已改变？** Obsidian 或其他程序修改了原文件。关闭弹窗，刷新后重新编辑；管家不会覆盖外部新内容。

**为什么资源没有出现在项目里？** 检查资源条目的“适用项目”是否包含当前项目编号；项目筛选可清除。

**为什么资源状态是“已测试”但实际上不能用？** 状态是人工登记，不是自动连接或检测结果。

**为什么“最近工作”为空？** 它记录从今日进入项目的使用时间，不读取 Agent 私密对话来推断。

**为什么 U 盘换电脑找不到知识库？** 原目录在 U 盘外，需要携带 / 恢复并重新选择。选择资料位置不会自动移动旧文件。

**恢复会覆盖正在用的文件吗？** .amb 默认只写新目录 / 空目录；Hermes 原生恢复遵循原有退出、预览、救援与确认流程。

**启动 DLL 错误怎么办？** 用对应系统的完整新运行包解压，不混用历史 _internal 文件；源码需虚拟环境与完整 Qt 依赖。仍失败时检查数据安全里的诊断或运行包启动诊断。
